**p4n4-dashboard 1.1.1** makes the service's restart policy configurable. The image is unchanged from 1.1.0; only `docker-compose.yml`, `docker-compose.tls.yml` and `.env.example` change.

```bash
docker pull ghcr.io/raisga/p4n4-dashboard:1.1.1    # amd64 and arm64
```

> **Trusted networks only,** like the rest of p4n4 0.2.x. Keep port 8088 on your LAN. If it must be reachable from elsewhere, serve it over HTTPS (`docker-compose.tls.yml`) with basic auth on.

## Highlights

- **`RESTART_POLICY`** in `.env` sets the container's restart policy (`restart: ${RESTART_POLICY:-unless-stopped}`). The default is still `unless-stopped`, which brings the dashboard back after a reboot or a Docker restart. Set `RESTART_POLICY=no` to keep it down until the next `docker compose up -d`, e.g. on a workstation that switches between projects. `always` and `on-failure` work too.

## Compatibility

- Same as 1.1.0: use with **p4n4-api 0.1.0**.
- The p4n4 stacks (iot, ai, edge) and the template registry read the same `RESTART_POLICY` variable, so one setting per layer `.env` covers a whole project.

## Upgrading from 1.1.0

- Nothing to do: without `RESTART_POLICY` the service behaves as before. To use it, add `RESTART_POLICY=no` (or another policy) to your `.env` and run `docker compose up -d`, which recreates the container with the new policy.
