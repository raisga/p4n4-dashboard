**p4n4-dashboard 1.5.0** opens p4n4's web apps inside the dashboard: Grafana, Node-RED, InfluxDB, n8n and Swagger UI, served through the dashboard's own origin where that's needed. It also makes the Feed a place to review alerts one after another.

```bash
docker pull ghcr.io/raisga/p4n4-dashboard:1.5.0    # amd64 and arm64
```

> **Trusted networks only,** like the rest of p4n4. Keep port 8088 on your LAN. If it must be reachable from elsewhere, serve it over HTTPS (`docker-compose.tls.yml`) with basic auth on.

## Highlights

- **Services open in the app.** Tapping Grafana, Node-RED, InfluxDB, n8n or Swagger UI on the Services tab opens it in a viewer: in place of the cards on wide screens, on a page of its own on phones. Its toolbar has back, reload and *Open in browser*. Instead of an empty frame, the viewer says when:
  - the service is down;
  - this platform can't embed pages (Windows and Linux, which offer the browser instead);
  - the page refused to be framed, or is plain HTTP on an HTTPS dashboard;
  - nothing has loaded after 15 seconds.

  Viewers get plain words and never a host or URL. The APIs (Ollama, Letta, p4n4-api, the inference runner) and MQTT still open in the browser, if at all.
- **The Grafana tab uses the same viewer,** with its kiosk mode, the app's light or dark theme and each view's own page. The theme now survives signing in to Grafana, through `/grafana/` and in the native apps.
- **A URL per service:**
  - Settings → Endpoints, on the device;
  - `dashboard.services` in the project's `.p4n4.json`;
  - `serviceUrls` in `config.json` (set from the dashboard's `.env`).

  Without one, a service opens at its port on the host; p4n4-api and Swagger UI follow the API's base URL.
- **Same-origin routes** (opt-in in the dashboard's `.env`): `/svc/node-red/` and `/svc/n8n/`, beside the existing `/grafana/`. Swagger UI is always served this way. They're what makes the apps work behind HTTPS, and n8n at all, since it refuses other sites' frames. These routes:
  - pass WebSockets through;
  - never forward the p4n4-api token or basic auth credentials;
  - let only the dashboard frame them.

  With basic auth on, Node-RED's editor works through its route too.
- **A tighter content policy:** the dashboard may frame only itself, the services' own addresses, and the origins in `DASHBOARD_FRAME_ORIGINS` (previously any page).
- **Truer service status:**
  - When p4n4-api can't report it, each web app is checked where it opens, so a proxied service with no published port shows as up.
  - On an HTTPS dashboard, a plain-HTTP service shows as unknown rather than offline.
  - When p4n4-api answers without status (Docker access off, or the daemon down), the Services tab says so, with its reason, instead of "can't reach".
- **The Feed, for reviewing alerts:**
  - Tapping an item opens it in full: its picture as large as the screen allows (pinch or scroll to zoom), everything it says, its link and its actions.
  - The keyboard drives it: `1`, `2`… take the actions, `J`/`K` or the arrows move between items, `Esc` goes back. After an action it moves on to the next item still to review.
  - Pending alerts show their picture as a thumbnail in the list.
  - The status `confirmed` is shown translated.
- **Teams on recorded video:** a box in a vision recording can name the person's kind (for example, their team), which draws and labels the box in that kind's colour.

## Compatibility

- Works with **p4n4-api 0.3.0**. Feed pictures and links need the next p4n4-api, which relays them (`GET /api/v1/feed/{id}/image`); with 0.3.0, items show without them.
- The same-origin Node-RED and n8n routes need the stacks' path settings: `NODE_RED_ADMIN_ROOT` in p4n4-iot and `N8N_PATH` in p4n4-ai. Both are on the stacks' `main`, which new projects (`p4n4 init`) get.
- `.env.example` pins `DASHBOARD_VERSION=1.5.0`.

## Upgrading from 1.4.0

- Set `DASHBOARD_VERSION=1.5.0` in the dashboard layer's `.env`. Without the new settings, every service opens at its port as before.
- **Content policy:** if you open a service at a host the dashboard doesn't know (Settings → Endpoints), add that origin to `DASHBOARD_FRAME_ORIGINS`, or the browser won't show it.
- **To serve Node-RED or n8n through the dashboard:**
  - Set `NODE_RED_UPSTREAM` and `DASHBOARD_NODE_RED_BASE=/svc/node-red/` (or the n8n pair) in the dashboard's `.env`.
  - Set the matching path in the stack's `.env`: `NODE_RED_ADMIN_ROOT=/svc/node-red/` or `N8N_PATH=/svc/n8n/`.
  - A project created before these settings needs the stack files that read them, from p4n4-iot's `config/node-red/settings.js` and `docker-compose.yml` and p4n4-ai's `docker-compose.yml`.

  The README's Services section has the details.

## Limitations

- **Same-origin pages share the dashboard's origin.** A page served through `/grafana/` or `/svc/<id>/` can read the dashboard's browser storage (on web, the refresh token too) and call `/api/` as the signed-in user. Proxy only services you trust as much as the dashboard.
- **InfluxDB can't go behind the dashboard's HTTPS:** its interface can't serve from a sub-path. Behind HTTPS, the viewer explains that and offers the browser.
- **Some refusals can't be seen.** The browser doesn't say when another origin's page refused to be framed, so the viewer offers a dismissible "Blank?" hint.
- **Grafana's theme:** Grafana's own login page keeps the user's theme. A Grafana framed from another origin keeps it after sign-in, until it's reopened.
- **Not tested:** the viewer was checked in Chromium and Firefox, over HTTP and behind `docker-compose.tls.yml`, but not in Safari or in the native apps' web views.
- The new labels in languages other than English haven't been reviewed by native speakers.
